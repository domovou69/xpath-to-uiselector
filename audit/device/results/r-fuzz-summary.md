# R fuzz run on the emulator

Generated by `audit/device/fuzz.js` from `r-fuzz.json` (2026-10-21). Stack: appium 3.8.0, uiautomator2 driver
8.7.0, server 10.6.6; AOSP_API_36, Android 16 (API 36); default settings.

Items: the 1169 distinct XPaths of the 1198 converted Android literals of the R corpus (exact and close,
[convert-summary.md](../../corpus/convert-summary.md)). Screens: 45 (9 batches of ≈130 items, 5 screens each,
103–751 nodes, seed `r-fuzz-1`, [r-fuzz-screens.json](r-fuzz-screens.json)), built by [fuzz-screens.js](../fuzz-screens.js) from
each XPath: targets (plain, deeper, nested, invisible, n+1 for a position), near misses with one value changed, and
for `//A//B` B outside A, A inside A, two Bs in one A. Every item runs on every screen of its batch. A batch is
smaller than the planned ≈500 because a screen travels in one `am start` argument (128 KB on the device).

CORRECT: EQUAL on every screen, with a match on the item's own screen. DRIFT: a close form (childSelector,
android.view.View, lower-case) whose first element agrees on every screen. Close forms that only warn about a
runtime value are held to EQUAL, since the fuzz fills in safe values. VACUOUS: no match on the item's own screen.

What the device sees is the XPath after the scanner has read the source literal. How the literal is written in the
source (quotes, escapes, `String.format`, f-strings, concatenation) and how the UiSelector is written back are
checked by the unit tests (`npm test`) and offline per language ([convert-summary.md](../../corpus/convert-summary.md)), not here.

Not run: 1 converted XPath the screen builder cannot read (call matches),
covered by the edge cases instead.

## Matrix screens

Every item once more, on 105 screens of its own kind (seed `r-fuzz-matrix-2`, 248–851 nodes), run only on its own screen. A matrix
cell breaks every tested condition of every level in every way that applies to it: for a string one character more
or less at either end, the case swapped, a space around it or a no-break space in it, null, "", the value in
another attribute, a resource id without its package, and the strings that the value read as an unescaped regex
matches (`.` → `x`, `a+b` → `aab`, `(x)` → `x`); for contains / starts-with the value broken in place or moved to
the other end; similar classes (`ImageButton` for `Button`, another package, `…Compat`, lower case, none); booleans
flipped; the index moved by one with an invisible sibling before it. Targets: every alternative, deeper, nested,
with line breaks around a contains / starts-with value and with the bare value; invisible ones (hidden, in a hidden
box, no size) and a hidden match first in the cell; union branches also in reverse document order.

Verdicts: CORRECT 1089, DRIFT 80, WRONG 0, VACUOUS 0, not run 0.

## Mutants

Do the screens catch a wrong conversion? A mutant is a wrong UiSelector made from an exact item's own, the kind
of error a converter could make (the converter never emits these: its rules and the S cases on the device keep it
to exact forms). Each mutant runs on its item's own screen; it is killed when the result differs from the XPath's.
Up to 150 items per kind, the first in key order. A survivor is a mutant that no element of the screen tells apart.
